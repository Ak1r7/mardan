# Краткая модель угроз

## Реализованные меры
- серверная валидация всех полей;
- ограничение размера запроса и длины данных;
- honeypot и минимальное время заполнения формы;
- same-origin проверка при наличии заголовка `Origin`;
- rate limiting с блокировкой файла от гонок;
- заявки хранятся вне публичного доступа, IP сохраняется только в виде хеша;
- CSP, запрет iframe, MIME sniffing, directory listing и доступ к служебным каталогам;
- отсутствуют `eval`, `innerHTML`, собственная криптография, БД и авторизация.

## Остаточные риски
- файловое хранилище зависит от корректной настройки Apache и прав каталогов;
- rate limiting по IP/User-Agent не заменяет WAF и может обходиться распределёнными запросами;
- нет антивирусной проверки, потому что загрузка файлов не реализована;
- нет админ-панели, платежей и учётных записей;
- перед production требуется независимая проверка конфигурации хостинга, TLS, резервного копирования и политики удаления данных.
